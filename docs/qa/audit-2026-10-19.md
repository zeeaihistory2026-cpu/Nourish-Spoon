# Code and commerce audit — 19 October 2026

## Findings and fixes

1. Production orders existed with canonical `created_at`, `status` and `customer_uid` fields, while the deployed dashboard read legacy camel-case fields. Local dashboard adapters now query the canonical records; no customer orders are deleted or rewritten by cleanup.
2. Missing delivery configuration left customer orders awaiting a manual quote. One shared delivery calculator now implements Rs. 250 shipping, free above Rs. 2,500 after discounts, and free pickup. Confirmation resolves an old pending quote using that policy.
3. The callable entry point duplicated checkout and fulfilment logic. Both server transports now use the same transactional services, including stock, discounts, reward settlement and notifications.
4. Dashboard views loaded once. Live Firestore invalidation refreshes orders, tracking and summary views, with a visible-tab API refresh fallback. The app subscribes to its own orders, inbox, reward wallet and ledger.
5. Dashboard referral settings and records were separate from the customer program. Settings now update `settings/rewards`, and referral linkage, paid delivery and refund transactions update the dashboard records. The misleading metadata-only correction control was removed; manual point corrections use the audited points endpoint.
6. The obsolete Vite dashboard coexisted with the selected Next.js dashboard and excluded real routes from TypeScript checks. Its entry points and six unused editors were removed. Strict unused-symbol checks are enabled in both apps.
7. Unused hero images, generated crop experiments and starter SVGs were removed. The recovery archive and SHA-256 removal manifest are in ignored `artifacts/`.
8. Preset sale prices are removed from the bundled catalogue. Live catalogue changes require a backup and update-time preconditions; past order prices remain historical records.
9. The Firebase Admin CommonJS runtime check uses a scoped `jwks-rsa` / `jose` compatibility override. Dashboard export removes deleted generated routes, preventing stale code from surviving deployment.
10. The other agent's latest GitHub dashboard banner, layout and login password visibility changes were preserved.
