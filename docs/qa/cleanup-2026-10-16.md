# Structural cleanup — 16 October 2026

This follow-up implements a deeper structural and visual cleanup after the [initial audit](codebase-audit-2026-10-16.md). Changes remain local and have not been deployed or packaged as a native release.

## Changes

- Split the mobile entry point into an error boundary, app shell, screen composition, startup hook, account lifecycle hook and navigation controller. Pure route helpers own tab and menu selection. Removed unused navigation aliases and global selected-product state.
- Replaced separate home/catalogue card implementations with one product card. Cards use active variants, show the selected price, disable sold-out actions, and keep the favourite control separate from the product link. Rebuilt the catalogue around a virtualized list, search, category chips, recipe counts and reusable empty states.
- Split the dashboard into focused order, catalogue, review and delivery sections. Removed repeated order filtering and isolated mutation feedback/concurrency handling in a hook.
- Removed the obsolete compact card, unused notification action, duplicate animation logic, redundant button gradient and duplicated story content/state.
- Deleted 21 unused derived design images, in addition to the unused runtime login artwork removed in the initial audit. Retained ingredient extraction inputs, original design/product sources, font licences and assets used by native plugins.
- Added `npm run audit:assets` to the root check and CI path. It verifies 58 referenced asset files and rejects missing references or unused runtime images/fonts.

## Verification

- `npm run check` passed: strict mobile/admin TypeScript, asset audit, 29 regression tests and the dashboard production build.
- Expo production web export passed with 66 assets and approximately 2.1 MB of JavaScript.
- Production browser checks verified catalogue navigation, empty search and reset, 250g/500g price changes, favourite toggling without navigation, product details, guest cart sign-in and return to browsing. The catalogue had no horizontal page overflow at 320 px.
- Dashboard production compilation passed; authenticated dashboard writes were not exercised against the live project.
- Existing native launch artwork edits and the unrelated untracked `Noor-Ai/` project were preserved.

## Remaining requirements

The initial audit's deployment and dependency findings still apply. Commerce backend activation, live permissions/provider setup and a real order lifecycle require separate deployment verification. Firebase emulator integration remains blocked by the installed Java 17 runtime; the CLI requires Java 21+. Mobile/backend transitive dependency advisories and the dashboard large-chunk warning require tested upstream upgrades/performance work. No dependency downgrade or untested major upgrade was forced.
